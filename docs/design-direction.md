# design-direction.md

## このドキュメントについて

- このドキュメントは、Citytoriの現在のデザイン方向と判断材料を整理するものです
- 確定仕様ではありません。実際の画面や利用体験を確認し、よりよい案があれば見直します
- プロダクトの目的やMVPは `docs/product-direction.md`、現在の画面と状態は `docs/current-ui.md` を参照してください

## デザインで目指すこと

- しりとりをしながら、日常の街を少し違う視点で歩きたくなる雰囲気をつくる
- 街の中で何かを探し、見つける楽しさが感じられるようにする
- 写真とことばで発見を気軽に残し、あとから振り返りたくなる体験にする
- 散歩中の記録を邪魔しない、分かりやすく読みやすいUIにする
- 散歩中の屋外利用を想定し、文字サイズ、色のコントラスト、操作しやすさを優先する

## 現在のデザイン方向

- 街歩き雑誌やZINEのような編集感を持ち、大人でも使いやすい
- UIの土台は静かに整え、ロゴ、キービジュアル、CTAなどのブランド部分で少し大胆に遊ぶ
- 大人っぽさを基調に、親しみやすさと少しのお茶目さを添える
- 写真とことばを主役にしつつ、トップでは散歩に出たくなるグラフィックをしっかり見せる
- 楽しさは装飾の量ではなく、太い線、色の強弱、余白のリズムでつくる
- 鳥や街並みは、Citytoriらしさを補助する存在として使う
- 既存レイアウトを維持すること自体は要件ではない

## 配色

### Base Colors

- Warm White: `#FCF9EF`
- White: `#FFFFFF`
- Deep Green: `#204D49`
- Orange: `#F16B36`（イラストのアクセント）
- Action Orange: `#B9471D`（白文字の主要操作・強調文字）
- Pale Aqua: `#E8F4F5`
- Cream / Character Background: `#FFF3DF`
- Charcoal: `#303B3C`
- Muted Gray Green / Border: `#C9DBD7`

### Illustration Accent Colors

- Leaf Green: `#88A485` — 街路樹や草花など、イラスト内の自然要素
- Mustard: `#E8B23F` — イラスト内の小さな遊び色。必要な場面だけ使う

- 白を基本に、生成り、水色、オレンジを面ごとに切り替えて画面にリズムをつくる
- オレンジは主要操作と注目させたい一点に使い、同時に多くのUIへ広げない
- ターコイズやピンクなどのポップな色は、必要になったときにイラストや企画的な表現へ限定して検討する
- 実装前に、文字・操作UIのコントラストを確認する

### Semantic Colors

ブランドカラーと状態色は役割を分ける。

- Success: 成功メッセージ専用
- Error: エラー表示専用
- Destructive: 削除など破壊的操作専用
- Warning: 必要な場合のみ使用

削除やエラーをOrangeなどのブランドカラーへ無理に統一しない。状態色は、意味が伝わることを優先する。

### UI Language

- 正式なサービス名は `Citytori`
- ロゴ表記は `citytori`
- `言葉` ではなく `ことば`
- `探す` ではなく基本的に `さがす`
- `タイムライン` ではなく `記録`
- `マップ` ではなく `地図`
- `投稿` / `登録` より `記録` を基本とする
- 写真取得は `写真を撮る`
- 保存操作は `写真とことばを記録する`
- 件数は `つないだことばの数`
- 位置関連は `位置情報`
- 活動名は `しりとり散歩`

## イラストとモチーフ

### 鳥

- 鳥はCitytoriらしさを補助するモチーフとして使う
- 案内、発見、完了などを補助する存在として扱う
- ヒーローでは太く、ひと目で形が分かる線を使う。小さな補助イラストは細めにしてよい
- 深緑の線を共通軸に、オレンジ、緑、淡い水色を少量だけ彩色する
- 強いマスコットキャラクターや子ども向けの表現にしすぎない
- 鳥の具体的なポーズ、服装、小道具、使用範囲は未確定

### 街並み

- 建物、木、街灯、看板など少ないモチーフを太い線で描き、スマホでも読み取れるようにする
- 背景や補助要素として使い、写真、ことば、主要操作を邪魔しない
- 必要に応じて木や街の一部だけに彩色を使う
- 日常の街を少し面白く見せるための、さりげない存在として扱う

## タイポグラフィと余白

- 本文、フォーム、地図などの情報は読みやすさを優先する
- 見出しと短いコピーは肉厚で少し丸みのある書体を使い、散歩雑誌の表紙のような力を持たせる
- 本文は読みやすいゴシック体を基本にし、見出しとの役割を分ける
- ヒーローではコピー、補足コピー、キービジュアルの間隔を詰め、ひとつのグラフィックとして見せる
- 写真やことばを主役にできる余白を確保する
- 装飾やイラストによって情報の優先順位を下げない

### Typography Scale

- Caption / annotation: 12〜13px
- Body / form value: 16px
- Card title / recorded word: 18〜20px
- Section heading: 20〜24px
- Page title: mobile 30〜32px / desktop 36〜40px

画面構造によって例外は認めるが、同じ役割では大きく差をつけない。

## 今後確認したいこと

- 主要CTAと補助操作に使う色の役割
- 成功、警告、エラーなど状態色の定義
- 鳥と街並みを使う画面・状態・密度
- 見出しと本文の書体、編集感を出す範囲
- 写真や記録より装飾が目立っていないか
- 全画面の情報の優先順位、ボタン、カード、見出しの統一
- カラーや余白などを実装用トークンとして整理する時期
